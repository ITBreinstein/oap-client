# The relay's SSRF threat matrix

The tests in this directory hold the relay to what it may send, and where,
before it faces the internet. One file per section, and every test name
carries its matrix ID. They use no real DNS and no network: `fixtures.ts`
injects the resolver and counts _connections_ at loopback stubs, so "nothing
was sent" is observed at a socket rather than inferred.

The matrix began as a tests-only PR (#15), with each gap it found pinned as an
expected failure. Each fix PR turned its own into an ordinary passing test.
None is left.

## Status per ID

**Safe** was already safe when the matrix was written, and is now pinned.
**Fixed** was a gap, closed by the PR named. **Accepted** is a known risk,
taken on purpose.

| ID  | What is tried                                                                                            | Status   | How it is held                                                                                                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | A scheme-relative path, `//evil.example/x`                                                               | Safe     | Refused as `absolute-url`; nothing sent                                                                                                                                                                                          |
| A2  | An absolute URL in the path, `/http://169.254.169.254/latest`                                            | Safe     | Refused as `absolute-url`                                                                                                                                                                                                        |
| A3  | A backslash, `/\evil.example/x`                                                                          | Safe     | Refused, whether the URL parser saw it first or not                                                                                                                                                                              |
| A4  | Encoded separators, `/%2F%2Fevil.example`                                                                | Safe     | Refused as `encoded-separator`. Decided: keep refusing them, rather than decode and re-check                                                                                                                                     |
| A5  | Userinfo in the path, `/https://testbed.example@evil.example/`                                           | Safe     | Refused as `absolute-url`                                                                                                                                                                                                        |
| A6  | Dot segments in any spelling, `/../../admin`, `/%2e%2e/admin`                                            | Safe     | Decided: the resolved path must stay under the base path. Refused as `dot-segment`                                                                                                                                               |
| A7  | The base URL repeated in the path, `/http://testbed.example/ogc/x`                                       | Safe     | Refused as `absolute-url`                                                                                                                                                                                                        |
| B1  | A redirect off the base                                                                                  | Safe     | Decided (ADR 0001): handed back to the browser unchanged, never followed. Zero connections to the target                                                                                                                         |
| B2  | A redirect to the same origin with userinfo                                                              | Fixed    | #16. `URL.origin` ignores userinfo, so it was followed, and Node then sent `Authorization: Basic`. `isUnderBase` now refuses any userinfo                                                                                        |
| B3  | A 307 under the base, then a 302 to loopback                                                             | Safe     | Every hop is checked again; the second is handed back                                                                                                                                                                            |
| B4  | A redirect loop                                                                                          | Safe     | Refused after `MAX_REDIRECTS` (3) hops                                                                                                                                                                                           |
| B5  | A redirect to an allowed path on the same origin                                                         | Safe     | Followed, through the address guard and DNS again. The asynchronous execute follows no redirect at all                                                                                                                           |
| C   | Blocked ranges as host literals: bracketed IPv6, names that only mean this machine or a metadata service | Safe     | Refused before any DNS                                                                                                                                                                                                           |
| C   | Un-normalised IPv4 as a host literal: `127.1`, `2130706433`, `0x7f000001`                                | Fixed    | #17. It was read as a name and refused only at connect time. Now refused as a literal, before DNS                                                                                                                                |
| C   | Blocked ranges as DNS answers                                                                            | Safe     | Refused at connect time, inside the socket's own lookup; a loopback stub sees zero connections                                                                                                                                   |
| D1  | DNS rebinding: a name that answers public first, then loopback                                           | Safe     | There is no pre-resolve to rebind against: the check runs in each fresh socket's lookup, for every hop and every read                                                                                                            |
| D2  | Public and private answers mixed                                                                         | Safe     | Refused as `blocked-address`, and nothing is dialled                                                                                                                                                                             |
| E   | `HEAD` on the read route                                                                                 | Fixed    | #18. Hono ran it through the `GET` handler, and a `GET` went upstream. Now refused, and nothing is sent. The web app stopped offering `HEAD` to that route in #87                                                                |
| E   | Any other method or path shape                                                                           | Safe     | Decided: only `GET` under the base, `DELETE` on `/jobs/{id}` and the execute `POST`. Everything else is refused with zero upstream calls                                                                                         |
| E   | Body and response caps, deadlines, the header allowlist                                                  | Safe     | Enforced while streaming, not after. Only allowlisted headers go upstream: no cookie, authorization, origin or forwarding headers                                                                                                |
| F   | What a block says, to the browser and in the log                                                         | Safe     | A bare reason code, with no address, host, port, token or query value                                                                                                                                                            |
| F   | A blocked asynchronous execute                                                                           | Fixed    | #19. It wrote no audit line. Every execute that got no answer now writes the read route's redacted line                                                                                                                          |
| G   | `allowPrivateNetwork` set on an endpoint                                                                 | Fixed    | #20. The flag alone switched the guard off. Now two keys: `RELAY_ALLOW_PRIVATE_ADDRESSES=1` _and_ the endpoint's flag. The startup warning names the endpoints, and a config that needs the variable refuses to start without it |
| H   | Guessing a callback token by timing                                                                      | Accepted | The token is a minted secret looked up in a `Map`, not compared character by character. Decided 2026-09-28: no constant-time compare, and no findings entry                                                                      |
| I1  | A forged `X-Forwarded-For` from a peer that is not a trusted proxy, to pick a fresh rate-limit key       | Fixed    | ADR 0003. The header is read only from a peer in `trustedProxies`, and then only its rightmost entry. Otherwise every forged name counts against the socket's address; the one over the limit reaches nothing upstream           |
| I2  | Many clients against one endpoint, each inside its own limit                                             | Fixed    | ADR 0003. A per-endpoint ceiling across all clients, per minute and in flight, refused as `rate-limited-endpoint` before anything is sent                                                                                        |
| I3  | Slow bodies that hold the relay's upstream connections open                                              | Fixed    | ADR 0003. A slot is held from send until the body is done or broken off, per client and per endpoint; the request over either refuses without a connection                                                                       |
| I4  | Many addresses from one IPv6 allocation: a /48 holds 65 536 /64s                                         | Accepted | Each /64 is one client. At `maxTrackedClients`, newcomers share one overflow entry rather than each getting a fresh allowance, and the per-endpoint ceiling still bounds what reaches a server                                   |
| I5  | Many people behind one address: a plugfest or an expo hall                                               | Accepted | They share one client's limits. Raised for an event in the config and redeployed (apps/relay/README.md, "Rate limits"); never switched off                                                                                       |

## Outside this matrix, and fixed

A followed redirect's body was drained with no cap and no deadline (review
R8). Followed redirects are now dropped unread (#54).
